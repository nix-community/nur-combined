# one-api

[One API](https://github.com/songquanpeng/one-api) built from source: the Go
backend plus all three bundled React web UI themes (`default`, `berry`, `air`)
are compiled into one binary.

## Lockfiles

Upstream does not commit npm lockfiles (its Dockerfile runs `npm install`), so
reproducible frontend builds need one. `locks/<theme>/package-lock.json` are
generated by `update.py`, committed here, and copied into `web/<theme>` during
`postPatch`. Each theme's dependencies are prefetched with `fetchNpmDeps`.

Update with the package's own script; it bumps the version and source hash,
regenerates the lockfiles, re-pins every npm deps hash and `vendorHash`, then
builds the package:

```sh
git add by-name/on/one-api
nix run .#one-api.passthru.updateScript
```

## NixOS module

```nix
# flake.nix
inputs.nurpkgs.url = "path:/path/to/nurpkgs"; # or github:<owner>/nurpkgs

# in nixosConfigurations.<host>.modules (or a configuration.nix imported there)
inputs.nurpkgs.nixosModules.one-api
{
  services.one-api = {
    enable = true;
    port = 3000;
    environmentFile = "/run/secrets/one-api.env";
  };
}
```

The service runs as a `DynamicUser` with its state in `/var/lib/one-api`
(SQLite database, logs, tiktoken cache), a 0077 umask and no capabilities.
The firewall is closed by default because one-api only speaks HTTP; front it
with a TLS terminating reverse proxy.

Security notes:

- Keep secrets in `environmentFile` (read by systemd as root, so mode 0400 is
  fine), never in `environment` — that is written to the world-readable store.
- Set `SESSION_SECRET` to a fixed random string. Without it one-api generates a
  new key on every start and logs everyone out.
- On a fresh database one-api creates `root` / `123456`. Log in and change
  that password immediately. `INITIAL_ROOT_ACCESS_TOKEN` and
  `INITIAL_ROOT_TOKEN` pre-seed the root management/API tokens; neither
  replaces the password.
- The database holds upstream provider API keys; treat `/var/lib/one-api` as
  secret material and back it up accordingly.
