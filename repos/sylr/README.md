# nur-packages

**sylr's [NUR](https://github.com/nix-community/NUR) repository**

![Build and populate cache](https://github.com/sylr/nur-packages/workflows/Build%20and%20populate%20cache/badge.svg)
[![Cachix Cache](https://img.shields.io/badge/cachix-sylr--nur--packages-blue.svg)](https://sylr-nur-packages.cachix.org)

Most packages here are generated by [GoReleaser](https://goreleaser.com/customization/publish/nix/)
when a project is released, the same way as in
[sylr/homebrew-tap](https://github.com/sylr/homebrew-tap). Those download the
prebuilt release artifacts from GitHub; nothing is compiled.

A few packages are written by hand and built from source:

- `git-sylr`: git from [sylr/git](https://github.com/sylr/git), upstream git
  plus `.gitcleanignore` support (`git check-cleanignore`). It overrides the
  nixpkgs `git` package, and CI pushes builds for x86_64-linux, aarch64-linux
  and aarch64-darwin to the binary cache below. To get those builds instead of
  compiling, use the flake's package as is: don't make its `nixpkgs` input
  follow yours.

## Usage

### Flake

```nix
{
  inputs.sylr.url = "github:sylr/nur-packages";

  outputs = { self, nixpkgs, sylr, ... }: {
    # e.g. in a NixOS, nix-darwin or home-manager configuration:
    # environment.systemPackages = [ sylr.packages.${system}.<name> ];
  };
}
```

Or run a package directly:

```sh
nix run github:sylr/nur-packages#<name>
```

### NUR

With [NUR](https://github.com/nix-community/NUR#installation) set up, the
packages are available as `pkgs.nur.repos.sylr.<name>`.

### Overlay

[`overlay.nix`](./overlay.nix) adds the packages directly to `pkgs`.

### Binary cache

CI pushes the built packages to
[sylr-nur-packages.cachix.org](https://sylr-nur-packages.cachix.org):

```nix
nix.settings = {
  extra-substituters = [ "https://sylr-nur-packages.cachix.org" ];
  extra-trusted-public-keys = [ "sylr-nur-packages.cachix.org-1:Ln+jB5uQKjGqqrVW7ggWa0joL4bKyOSdr4t80ejAAHE=" ];
};
```

## Adding a package

Any directory under [`pkgs/`](./pkgs) is exposed as a package named after the
directory. GoReleaser writes `pkgs/<name>/default.nix` itself, so publishing a
new project only needs a `nix:` section in its `.goreleaser.yaml`. This needs
GoReleaser 2.19 or later: `main_program` arrived in 2.16, and before 2.19 the
publisher also needs `nix-hash` in `PATH` and is skipped without it.

```yaml
nix:
- name: <name>
  repository:
    owner: sylr
    name: nur-packages
    token: "{{ .Env.NUR_GITHUB_TOKEN }}"
  homepage: "https://github.com/sylr/<project>"
  description: "..."
  license: mit # a nixpkgs lib.licenses attribute name, not an SPDX id
  main_program: <binary>
```

The token needs Contents write access to this repository.
