# `work-planning` composition

- **Target and responsibility:** Repository-first, decision-complete planning with observable acceptance criteria.
- **Sources:** [Everything Claude Code](https://github.com/affaan-m/ECC) `skills/intent-driven-development/SKILL.md`, “When to Activate,” context, acceptance, and handoff; [oh-my-openagent](https://github.com/code-yeongyu/oh-my-openagent) Prometheus agent, interview, exploration, and one-plan sections; current [oh-my-openagent](https://github.com/code-yeongyu/oh-my-openagent) `packages/shared-skills/skills/ulw-plan/SKILL.md`, explore-first and decision-complete planning; [spec-kit](https://github.com/github/spec-kit) `templates/spec-template.md` and `templates/commands/{specify,clarify,checklist,analyze,plan}.md`, the plan phase's `research.md`, `data-model.md`, and `contracts/` as conditional design artifacts beside the spec, spec structure, identifiers, marker cap, informed defaults, question format, coverage taxonomy, refinement protocol, persisted requirements checklist, and domain checklists; [ai-native-engineering-workspace](https://github.com/engindemirog/ai-native-engineering-workspace) `specs/TEMPLATE.md`, `specs/TEMPLATE-mini.md`, and `prompts/{spec,plan,verify}.md`, status lifecycle, preserved behavior, criterion ↔ test map, and hostile-reader critique, plus `workflows/refactor.md`, green baseline, characterization tests, and unchanged-test proof for behavior-preserving plans; OpenSpec and Kiro public documentation, living-spec deltas and EARS patterns.
- **Behavior taken:** A `commits` field and Commit strategy section asked only for multi-task or phased plans; Quick versus full depth, questions only for non-discoverable choices, an extrinsic-constraint sweep (budget, stack, scale, audience), full-scope planning with no invented MVP, a gap analysis before handoff, a human Summary, four-dimension final verification, explicit scope/decisions, per-task evidence, durable draft handoff, explicit approval before execution, and an opt-in Spec First mode with its own contract, quality passes, and plan traceability, plus local user-requested optional phased delivery for plans whose total PR would not be reviewable.
- **Merge:** Acceptance-brief discipline and OMO planning are combined into a short routing skill with separate plan and acceptance references; spec-driven references (`spec-contract.md`, `spec-quality.md`) sit beside them so `/ac:spec` and `/ac:plan` share one vocabulary. The plan contract owns the optional phase mapping, branch/PR topology, and final umbrella verification.
- **Provider adaptation:** Plans live in `.agents/work`, specs in `specs/` at the project root; provider draft state, tool-call examples, helper scripts, and model routes are absent.
- **Exclusions:** Separate constitution, checklist, tasks, and implement stages, mandatory interviews, runtime ledgers, fixed task grammar, branch automation, and provider approval machinery were excluded.
