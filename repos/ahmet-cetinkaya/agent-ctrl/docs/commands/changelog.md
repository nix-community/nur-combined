# `/ac:changelog` composition

- **Target and responsibility:** Build evidence-based, user-facing release notes and synchronize existing changelog/store targets without releasing.
- **Sources:** current `git-workflow` history discipline.
- **Behavior taken:** Resolve a release range, inspect full diff/history, group observable user impact, preserve repository format, enforce platform limits, and verify every claim.
- **Merge:** Legacy rewrite behavior is grounded in explicit Git evidence and expanded with stop/authorization boundaries.
- **Provider adaptation:** Uses standard Git/history concepts; no provider-specific agent or model routing.
- **Exclusions:** Guessed benefits, invented versions/dates, tag/version bump, commit, push, localization guessing, publish, and release.
- **Attribution:** Original content written for this catalog.
