# `/ac:spec` composition

- **Target and responsibility:** Explicit checkpoint for writing or refining one behavior spec that the user approves before `/ac:plan` designs the implementation.
- **Sources:** [spec-kit](https://github.com/github/spec-kit) `templates/commands/specify.md`, short-name and numbering rules, informed defaults, marker cap, and self-validation loop; [spec-kit](https://github.com/github/spec-kit) `templates/commands/clarify.md`, coverage taxonomy, one-question-at-a-time refinement with recommended answers, and the clarifications log; [spec-kit](https://github.com/github/spec-kit) `templates/spec-template.md`, prioritized user stories with priority reasons and independent tests, key entities, `FR-###`/`SC-###` identifiers, edge cases, and assumptions; [spec-kit](https://github.com/github/spec-kit) `templates/commands/checklist.md`, requirements-quality checklists as unit tests for the requirements text; [ai-native-engineering-workspace](https://github.com/engindemirog/ai-native-engineering-workspace) `prompts/spec.md` and `specs/TEMPLATE-mini.md`, hostile-reader self-critique, preserved-behavior criteria, the spec-size split signal, and the draft/approved/in-progress/shipped lifecycle; [ai-native-engineering-workspace](https://github.com/engindemirog/ai-native-engineering-workspace) decision records, a required user-experience section and struck-through descoping; OpenSpec public documentation, living spec plus ADDED/MODIFIED/REMOVED deltas merged on archive; Kiro public documentation, EARS requirement patterns; [SuperClaude Framework](https://github.com/SuperClaude-Org/SuperClaude_Framework) `src/superclaude/commands/brainstorm.md`, problem-before-solution questioning and alternative comparison.
- **Behavior taken:** Repository-first discovery, one change spec per run under `specs/changes/<NNNN>-<slug>/`, EARS requirements with Given/When/Then scenarios, a required user-experience section with one scenario or requirement per state, a split recommendation for specs spanning more than one capability or ten requirements, struck-through descoping after approval, delta and preserved-behavior blocks for changes to existing capabilities, at most three clarification markers, informed defaults instead of questions, a structured question format (full interrogative, why it matters, recommended option, option table), checklist and hostile-reader passes recorded in `checklists/requirements.md`, an on-request domain checklist (`--checklist`), in-place refinement on re-run with immediate write-back, conflict replacement, term normalization, Deferred areas, and a checklist re-evaluation, and explicit user approval before planning.
- **Merge:** The former `/ac:brainstorm` command is folded in as a direction-settling step that runs before any file is written. spec-kit's `specify` and `clarify` collapse into one command whose second mode is triggered by passing an existing spec path. `checklist` becomes the `--checklist` mode. `analyze`, `tasks`, `implement`, and `converge` are not separate commands: analyze's detection passes run in `/ac:plan-review`, converge's gap types in `/ac:verify`, and the rest live in `/ac:plan`, `/ac:plan-review`, `/ac:run`, and `/ac:verify` through the traceability and deviation rules in `work-planning/references/spec-contract.md`.
- **Provider adaptation:** Specs live in `specs/` at the project root rather than provider-private or tool-specific directories; no bash or PowerShell helper scripts, extension hooks, feature pointer files, or branch automation are used — the agent performs numbering and directory creation directly.
- **Exclusions:** Constitution as a separate artifact (the project's own instruction files serve that role), extension hooks, `.specify/feature.json` pointers, task-list grammar, GitHub issue export, automatic commits, and provider runtime state were omitted.
