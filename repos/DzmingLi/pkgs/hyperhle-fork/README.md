# HyperHLE-Fork

The package uses the checked-in `Cargo.nix` generated by crate2nix. Normal NUR
expression evaluation does not run Cargo, crate2nix, or import a derivation.
The repository's `flake.lock` pins the tool versions used by the updater.

## Update

From the repository root:

```sh
nix run .#hyperhle-fork.updater
nix run .#hyperhle-fork.updater -- --version v1.0.92
nix run .#hyperhle-fork.updater -- --regenerate
```

The default selects the latest stable GitHub release. `--regenerate` keeps the
current revision and recreates the generated inputs. The updater regenerates
`Cargo.nix`, Git crate hashes, source component hashes, and the runtime dependency
license list. It checks that Cargo.lock was not changed, applies carried patches,
evaluates without IFD, and builds before keeping the generated files. A failed
validation restores the original generated files. `--no-build` is available for
working on the generator; CI uses the default full build.

The updater never edits generated Nix expressions by hand; it only normalizes
their final newline. Source and dependency overrides live in `unwrapped.nix`.
If a release already includes a carried patch, reconcile the patch list in both
`unwrapped.nix` and the updater before updating. An unexpected patch failure is
intentional: do not silently discard a compatibility fix.

`fix-ctype-exports.patch` implements the guest C character functions needed by
三国杀－烈's victory settlement ([upstream PR #126](https://github.com/KlugKlugTG/HyperHLE-Fork/pull/126)).
`fix-sigsetjmp-exports.patch` separately exports the existing guest jump-buffer
implementation; it was not the cause of the settlement failure.

## Build and cache boundaries

- `unwrapped`: crate2nix compiles each crate separately. The final executable uses
  release optimization, one codegen unit, and fat LTO.
- `resources`: fonts, emulated libraries and default game options.
- The final package only installs the launcher and links the above outputs.
  Editing IAP defaults or the launcher does not rebuild Rust code.

`source-layout.json` describes each local crate and its required vendor files.
The updater computes recursive NAR hashes for these slices. Fixed-output source
slices retain their output paths across upstream revisions when their contents
are unchanged. Their directory structure is preserved for relative C includes
and build scripts. Nixpkgs' crate builder is told the explicit workspace member,
so these isolated source trees do not need a complete Cargo workspace.

SDL and OpenAL use Nixpkgs libraries; Boost is a system build input. Dynarmic,
stb, PVRTDecompress, libxml2, and the patched AAC decoder retain their pinned
upstream sources. The license list is generated from normal transitive Cargo
dependencies (all targets), excluding build/dev-only dependencies, and is
consumed by the patched upstream build script without running Cargo again.

The buildRustCrate adapter retains dependency bitcode. Its binary compiler
options are amended for fat LTO because the builder otherwise shares one option
list between the rlib and executable. The amendment has an evaluation assertion
so a Nixpkgs builder change cannot silently disable that optimization.

## Defaults

The launcher prefers Wayland when `WAYLAND_DISPLAY` is set and enables local
IAP emulation. `TOUCHHLE_IAP_EMULATION=0` disables that default. Data goes under
`${XDG_DATA_HOME:-$HOME/.local/share}/hyperhle-fork`; the package's immutable
resources are linked there. 三国杀－烈 uses the iPhone 4 guest profile.
