# Game servers k3s prep — multi-arch day 1 (2026-11-18)

Standing requirement (user): game servers must deploy on x86_64 OR
aarch64 from day 1 — every image choice below must be a manifest list
or a per-arch nix build. No amd64-only images, no QEMU emulation.

## Current state (oracle-cloud, all `enable = true`, all x86_64)

- Minecraft (PaperMC 26.1.2 custom pkg `papermc-26_1_2`, 10G heap G1GC,
  LazyMC proxy protocol 775, `declarative = false`, state
  `/var/lib/minecraft`). Ports (module): java + alt-query + Bedrock UDP
  + Simple-Voice-Chat UDP + http map page. Player-facing via direct
  ports (no Traefik — TCP/UDP game traffic).
- VintageStory (custom pkg `VintagestoryServer`, state
  `/var/lib/vintagestory`, single TCP+UDP port).
- Terraria (TShock, state `/var/lib/terraria`, `world.wld` large,
  8 players, REST API :7878 behind Caddy on oracle).

## Arch analysis (verify at migration build time — hub/ghcr APIs)

- Minecraft: server jar is arch-neutral JVM bytecode. Risks: native
  mod libraries (audit Simple Voice Chat + any Geyser/Bedrock bridge
  at migration), LazyMC binary (Rust — compiles per-arch via nix, or
  upstream multi-arch image). LOW RISK, likely fine.
- Terraria TShock (.NET self-contained): check upstream releases for
  linux-arm64 artifacts. If missing, fall back to vanilla
  terraria-server (nixpkgs builds per-arch?) or keep x86-only with a
  nodeAffinity pin + documented exception. MEDIUM RISK — verify first.
- VintageStory (closed-source .NET): entirely dependent on upstream
  shipping linux-arm64 server tarballs. If upstream is x64-only, ARM
  is BLOCKED for this title (pin x86 + document, or drop from the
  ARM matrix). HIGHEST RISK — check FIRST, before any other game work.

## k3s shape (when migration starts)

- One StatefulSet per game (stable identity + local-path world state),
  TCP+UDP NodePorts on the host that runs it (game clients need
  direct ports; Traefik only for http extras like map pages / TShock
  REST — same split as today with Caddy).
- Images: manifest-list upstreams where they exist
  (itzg/minecraft-server is multi-arch and covers PaperMC + mods +
  RCON — strong candidate for Minecraft; check TShock/VS equivalents).
  Custom nix-built images must build for BOTH systems (no
  `system = "x86_64-linux"` pinning in the packaging).
- Worlds carry over (same seed discipline as everything else: stop,
  copy, chown, restart). RCON passwords + seeds via secretspec.
- LazyMC (sleep-when-empty) must survive the move (costs real money
  on oracle) — keep the proxy in front, same protocol/version pin.
