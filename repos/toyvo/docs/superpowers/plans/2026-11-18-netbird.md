# WireGuard → NetBird self-hosted — Plan

Date: 2026-11-18
Design: `docs/superpowers/specs/2026-11-18-netbird-design.md`
(dark control plane, 1:1 peer migration, oracle joins k3s as agent only)

## Task 1 — Pin + verify images (executor: agent)

- Registry-verify (expect 200): NetBird `management`, `signal`,
  `relay`, `dashboard` images at the CURRENT stable tag (check
  netbirdio/netbird GitHub release — pick latest stable, record
  verbatim). Official repo is `netbirdio/<component>` on Docker Hub.
- Record runtime UIDs (registry config-blob flow, monitoring precedent).
- Verify the tag set is self-consistent (all four from the same
  release — NetBird versions its components together).
- Verify: versions + UIDs recorded verbatim in
  `.superpowers/sdd/netbird/task-1-brief.md`.

## Task 2 — Control-plane manifests dark (executor: agent)

- New `modules/nixos/k3s-netbird.nix` (registered, NOT enabled):
  Deployments + ClusterIP Services for management/signal/relay/
  dashboard; PVC for management state (sqlite/postgres? — NetBird
  management supports sqlite for small deploys; check release notes,
  prefer sqlite/local-path to avoid another Postgres dependency);
  secrets wiring (TURN credentials, IdP client secret); Ingress for
  the dashboard + management/signal API (forward-auth OFF — the
  control plane must never depend on the gate it will eventually
  front? No — dashboard login goes THROUGH authentik OIDC, which is
  separate from forward-auth. Forward-auth stays OFF regardless).
- coturn/relay UDP ports via NodePort (STUN/TURN need direct UDP —
  same reason as game servers, off Traefik).
- Verify: `nix eval` renders all manifests, `nix build` green, NO
  cluster objects (module dark).

## Task 3 — Secrets + IdP wiring (executor: user + agent)

- User: create OIDC client in Authentik (provider + application for
  NetBird management, note client ID/secret), create TURN + management
  secrets in-cluster (kubectl-direct, established pattern).
- Agent: wire env/refs; document exact Authentik provider settings
  (issuer URL, scopes) in the plan.
- Verify: secret keys present; management Deployment references them.

## Task 4 — Control plane live, dark (executor: agent + user)

- Agent: enable module, switch, verify 4 pods Running + probes.
- User: open dashboard (direct NodePort or temporary Ingress),
  log in via Authentik OIDC (proves the IdP loop), create the
  10.100.0.0/24 network + enrollment keys.
- Verify: login works, network + setup keys exist, relay shows
  healthy in dashboard. NO peers enrolled yet.

## Task 5 — Peer migration 1:1 (executor: user, attended)

- One peer at a time (pixel first — lowest blast radius, then oracle):
  install netbird agent, `netbird up --setup-key`, verify new IP +
  LAN reachability (ping 10.1.0.3, open a gated app), THEN remove the
  old wg config for that peer (one host switch each).
- Router hub last (after both spokes are stable on NetBird): remove
  `wireguard.interfaces.wg0` + open the signal/relay ports instead.
- Rollback per peer: `netbird down` + re-add wg config (keys retained
  in sops until Task 6 closes them out).
- Verify: all three peers on NetBird IPs, old wg interfaces gone
  (`ip addr | rg wg0` empty everywhere), LAN + gated-app access green.

## Task 6 — Oracle joins k3s as agent (executor: agent + user)

- Agent: k3s agent config for oracle (server URL via NetBird IP,
  token from sops, `disableAgent = false`, NO cluster-init, NO etcd
  — agent role only), firewall for kubelet + pod network over the
  NetBird interface.
- User: switch oracle, verify `kubectl get nodes` shows oracle Ready
  (agent role), test pod scheduling + game-server reachability.
- Verify: oracle Ready, no etcd voting (member list shows it as
  non-voting/agent), game ports reachable, NetBird tunnel stable
  under k3s traffic.

## Rollback (any task)

- Pre-Task 5: nothing live (dark stack only) — disable module.
- Per peer (Task 5): old wg keys + configs retained until proven;
  re-adding a peer is one switch.
- Post-Task 5: full wg config restorable from git (modules deleted
  only after green + 1wk, same as the container cleanups).
- Oracle k3s (Task 6): remove agent config, node drains itself;
  games keep running on oracle natively throughout (no game migration
  in this project — that comes after).
