# Prowlarr Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prowlarr serves from k3s (local-path StatefulSet, hand-seeded data) behind the existing Caddy vhost; container service retired.

**Architecture:** New `nixcfg.k3sStarr.prowlarr` module generating StatefulSet + Service + Ingress from nas only; Caddy `upstreams` flip in a separate commit; manual rsync seeding.

**Tech Stack:** NixOS (`services.k3s.manifests`), linuxserver/prowlarr (pinned tag, PUID/PGID 351), Traefik Ingress, Caddy multi-upstream.

**Spec:** `docs/superpowers/specs/2026-10-26-prowlarr-design.md`

## Global Constraints

- SQLite on local-path ONLY, `nodeAffinity: nas`; never NFS.
- PUID/PGID = 351/351 (matches `ids.uids/gids.prowlarr` and POOL ACLs).
- Manifests from nas ONLY (single-writer rule).
- Old container service stays up until k8s instance verified; POOL data copied, never moved.
- `nix fmt` before commit; validation is eval + toplevel builds; switches + seeding + flip are manual, nas-then-router, each step revertible.

## Review Focus

- Wrong UID (fresh files owned by image-default user, ACLs break on write-back) — expect PUID/PGID env == 351 in rendered manifest; test in Task 1 pins it.
- Ingress host mismatch (typo vs Caddy vhost) — expect `prowlarr.diekvoss.net` in both rendered Ingress and Caddy output; test in Tasks 1-2 pins it.
- Pod scheduled off nas (affinity typo → pending or wrong-disk data) — expect pod on nas only; test in Task 3 pins it.
- Seeded into wrong volume dir (data silently ignored, fresh-setup UI) — expect seeded file listing to match source listing; test in Task 3 pins it.
- Old service disabled too early (split-brain *arrs lose indexer mid-verify) — ordering enforced: disable only after k8s verified; test in Task 3 pins order.

### Task 3: Manual deploy + seed + flip + retire (user)

**Files:** none (commands only).

- [ ] **Step 1: Deploy manifests dark**

  Switch nas. Then: `sudo k3s kubectl get statefulset prowlarr` exists, pod on nas (`-o wide`), PVC bound local-path. Ingress exists but gets no traffic (Caddy still points at container).
  Expected: all present, old service still serving (verify UI loads).

- [ ] **Step 2: Seed by hand**

  On nas: find volume dir (`sudo ls /var/lib/rancher/k3s/storage/` — newest `pvc-*_default_data-prowlarr-*`); `sudo rsync -a /mnt/POOL/starr/prowlarr/ <volume-dir>/`; `sudo k3s kubectl rollout restart statefulset/prowlarr`; verify seeded: `sudo k3s kubectl exec prowlarr-0 -- ls /config` shows migrated files (compare `ls /mnt/POOL/starr/prowlarr`).
  Expected: listings match.

- [ ] **Step 3: Verify k8s instance directly**

  Port-forward or via Traefik NodePort with Host header: `curl -s -o /dev/null -w "%{http_code}" -H "Host: prowlarr.diekvoss.net" http://10.1.0.3:30080/` — expect 200 (or app's redirect; compare against container `:9696` behavior). Check API key works (login or API call with the known key).
  Expected: behaves identically to container instance.

- [ ] **Step 4: Flip + verify + retire**

  Switch router (Caddy flip live). Verify `https://prowlarr.diekvoss.net` 200 with auth gate; stop k3s on one server → still 200. Then disable container prowlarr service (flip its `enable` to false in the starr module call / nas config), switch nas, confirm old port dead and k8s still serving.
  Expected: full cutover, no split-brain leftovers.
