# Lidarr Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lidarr serves from k3s (local-path sqlite + RW NFS media), data seeded from verified-live set, container retired.

**Architecture:** Extend `nixcfg.k3sStarr` with lidarr (StatefulSet + Service + Ingress + media PVC on existing `pool-media-rw`); Caddy upstreams flip; manual seed + verify + retire.

**Tech Stack:** NixOS (`services.k3s.manifests`), linuxserver/lidarr pinned `3.1.6.5079-ls46` (PUID/PGID 306), Traefik Ingress, Caddy multi-upstream.

**Spec:** `docs/superpowers/specs/2026-10-26-lidarr-design.md`

## Global Constraints

- SQLite on local-path ONLY, `nodeAffinity: nas`; media via existing `pool-media-rw` (no new PV).
- PUID/PGID = 306/306 (nixpkgs lidarr ids).
- Manifests from nas ONLY (single-writer rule).
- Seed ONLY from a verified-live set (`.backup` + `integrity_check` + count); never a blind top-level copy.
- Old container service stays up until k8s instance verified end to end; container never restarted mid-migration.
- `nix fmt` before commit; validation is eval + toplevel builds; switches + seeding + in-app reconfig are manual, nas-then-router.

## Review Focus

- Wrong UID (write failures, ownership drift) — expect PUID/PGID env == 306; test in Task 1 pins it.
- Media mount missing/wrong (imports fail) — expect `/mnt` backed by `lidarr-media` on `pool-media-rw`; test in Task 1 pins it.
- Pod scheduled off-nas (affinity typo) — expect pod on nas only; test in Task 3 pins it.
- Seeded from stale/wrong files (empty library, onboarding wizard) — expect artist count to match pre-migration count; test in Task 3 pins it.
- Retire-before-proof (downloads break) — ordering enforced: disable only after end-to-end download verified; test in Task 3 pins it.
