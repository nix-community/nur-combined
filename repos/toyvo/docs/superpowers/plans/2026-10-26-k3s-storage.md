# k3s Storage Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** NFS static PVs for shared POOL dirs + proven local-path DB pattern with dumps, no production migrations.

**Architecture:** NixOS NFS export on nas (v4-only); csi-driver-nfs + static PVs applied from nas only (single-writer Addons); scratch postgres StatefulSet proving write→dump→restore→verify, then full cleanup.

**Tech Stack:** NixOS (`services.nfs.server`), csi-driver-nfs (upstream pinned release yaml), k3s manifests + static PVs/PVCs, postgres official image, pg_dump CronJob.

**Spec:** `docs/superpowers/specs/2026-10-26-k3s-storage-design.md`

## Global Constraints

- NFSv4 only; exports are explicit per-directory; `root_squash` default, no `no_root_squash`; RW vs RO per consumer (media path read-only).
- Driver + PV manifests applied from nas ONLY (never duplicate across servers).
- DBs never touch NFS: StatefulSets use local-path + `nodeAffinity: nas`.
- ReclaimPolicy Retain on static PVs; proof resources fully deleted at the end.
- `nix fmt` before commit; validation is `nix flake show` + toplevel builds + node-level mount test BEFORE any k8s step; manual deploys nas-first.

## Review Focus

- NFS world-readable/writable export (wrong `*` or missing squash) — expect `exportfs -v` to show 10.1.0.0/24-scoped entries with squash; test in Task 1 pins it.
- DB accidentally scheduled off-nas (tolerations/affinity typo → pending pod or worse, local data on wrong disk) — expect scratch pod on nas only; test in Task 3 pins it.
- Unpinned upstream yaml (latest-tag drift breaking reproducibility) — expect pinned tag + hash recorded in the manifest source; test in Task 2 pins it.
- Proof leftovers polluting the cluster (scratch postgres/pvcs forgotten) — expect `kubectl get pvc,statefulset -A` clean of proof names at end; test in Task 3 pins it.
- Firewall too broad (NFS on non-LAN interfaces) — nas is LAN-only so global rule matches existing k3s/firewall practice; test in Task 1 pins ports.
