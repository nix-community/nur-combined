# Radarr Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Radarr serves from k3s (local-path sqlite + RW NFS media), data seeded from verified-live set, container retired.

**Architecture:** Extend `nixcfg.k3sStarr` with radarr (StatefulSet + Service + Ingress + media PVC on existing `pool-media-rw`); Caddy upstreams flip; manual seed + verify + retire.

**Tech Stack:** NixOS (`services.k3s.manifests`), linuxserver/radarr pinned `4.0.20.3014-ls324` (PUID/PGID 275), Traefik Ingress, Caddy multi-upstream.

**Spec:** `docs/superpowers/specs/2026-10-26-radarr-design.md`

## Global Constraints

- SQLite on local-path ONLY, `nodeAffinity: nas`; media via existing `pool-media-rw` (no new PV).
- PUID/PGID = 275/275 (nixpkgs radarr ids).
- Manifests from nas ONLY (single-writer rule).
- Seed ONLY from a verified-live set (`.backup` + `integrity_check` + count); never a blind top-level copy; container never restarted mid-migration.
- Old container service stays up until k8s instance verified (UI library match + split-brain reachability + pod write test); full download deferred by decision.
- `nix fmt` before commit; validation is eval + toplevel builds; switches + seeding + in-app reconfig are manual, nas-then-router.

## Review Focus

- Wrong UID (write failures, ownership drift) — expect PUID/PGID env == 275; test in Task 1 pins it.
- Media mount missing/wrong (no library access) — expect `/mnt` backed by `radarr-media` on `pool-media-rw`; test in Task 1 pins it.
- Pod scheduled off-nas (affinity typo) — expect pod on nas only; test in Task 3 pins it.
- Seeded from stale/wrong files (empty library, onboarding wizard) — expect movie count to match pre-migration count; test in Task 3 pins it.
- Retire-before-proof (split-brain breakage) — ordering enforced: disable only after UI + split-brain + write test all green; test in Task 3 pins it.

### Task 3: Manual deploy + seed + reconfigure + flip + retire (user)

**Files:** none.

- [ ] **Step 1: Deploy dark + verify pod**

  Switch nas. `kubectl get statefulset radarr`, pods on nas, PVCs bound (`config-radarr-0` local-path + `radarr-media` → `pool-media-rw`). Old container still serving.

- [ ] **Step 3: Split-brain connectivity + in-app reconfig BEFORE flip**

  From pod: reach `https://prowlarr.diekvoss.net` (API, not gate) and `http://10.200.0.2:4080` (qbittorrent). If either fails, STOP. Then in k8s Radarr UI: indexer → public prowlarr URL, download client → direct qbittorrent URL.
  Expected: both reachable, config saved.

- [ ] **Step 4: Pod write test + flip + retire**

  `kubectl exec radarr-0 -- touch /mnt/.write-test && rm` — proves the RW media path end to end. Then switch router (Caddy live), verify 200 + failover. Add `"radarr"` to `disabledServices`, switch nas, confirm old port dead and k8s still serving.
  Expected: cutover complete.
