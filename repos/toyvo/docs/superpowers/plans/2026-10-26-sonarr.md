# Sonarr Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sonarr serves from k3s (local-path sqlite + RW NFS media), data hand-seeded, URLs repointed, container service retired.

**Architecture:** Extend `nixcfg.k3sStarr` with sonarr (StatefulSet + Service + Ingress); new `pool-media-rw` static PV; Caddy upstreams flip; manual seed + in-app URL reconfiguration.

**Tech Stack:** NixOS (`services.k3s.manifests`), linuxserver/sonarr pinned `4.0.20.3014-ls329` (PUID/PGID 274), Traefik Ingress, Caddy multi-upstream.

**Spec:** `docs/superpowers/specs/2026-10-26-sonarr-design.md`

## Global Constraints

- SQLite on local-path ONLY, `nodeAffinity: nas`; media via NFS RW PV; never sqlite-on-NFS.
- PUID/PGID = 274/274 (nixpkgs sonarr ids, existing ownership).
- Manifests + PV from nas ONLY (single-writer rule).
- Old container service stays up until k8s instance verified end to end (real download, not just UI).
- `nix fmt` before commit; validation is eval + toplevel builds; switches + seeding + in-app reconfig are manual, nas-then-router.

## Review Focus

- Wrong UID (fresh files misowned, import writes fail) — expect PUID/PGID env == 274 in rendered manifest; test in Task 1 pins it.
- Media mounted RO (imports fail silently or error) — expect the media mount backed by a RW PVC (`pool-media-rw`), not `pool-public-ro`; test in Task 1 pins it.
- Pod scheduled off-nas (affinity typo) — expect pod on nas only; test in Task 3 pins it.
- Seeded into wrong volume dir (fresh-setup UI, config gone) — expect seeded listing to match source listing; test in Task 3 pins it.
- Retire-before-proof (downloads break mid-flight) — ordering enforced: disable only after end-to-end download verified; test in Task 3 pins it.

- [ ] **Step 5: Flip + retire**

  Switch router (Caddy live). Verify `https://sonarr.diekvoss.net` 200, failover (stop k3s one server → still 200). Then add `"sonarr"` to `nixcfg.containers.starr.disabledServices`, switch nas, confirm old port dead (`10.200.0.2:8989` refused) and k8s still serving.
  Expected: cutover complete.
