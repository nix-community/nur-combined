# Jellyfin Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jellyfin serves from k3s (official image pinned to 12.4, UID 359, DRI passthrough, sqlite seeded from live state), container retired.

**Architecture:** New `nixcfg.k3sJellyfin` module (StatefulSet + Service + Ingress, RO media PVC, hostPath DRI); `homelab.nix` upstreams flip removes the edge route; manual seed + verify (incl. HW transcode test) + retire.

**Tech Stack:** NixOS (`services.k3s.manifests`), `jellyfin/jellyfin:12.4` (hub-verified, matches `pkgs.jellyfin` 12.4), Traefik Ingress, NFS `nfs-pool` RO media.

**Spec:** `docs/superpowers/specs/2026-11-14-jellyfin-design.md`

## Global Constraints

- Exact version pin 12.4 (no migration risk by construction).
- UID/GID 359 throughout (`runAsUser`/`runAsGroup` + `supplementalGroups` [26, 303] for DRI, `nodeAffinity: nas`).
- SQLite state on local-path ONLY; media read-only (never RW from the pod).
- Manifests from nas ONLY (single-writer rule).
- Seed ONLY from the verified-live set (394M); container untouched until seed day.
- No dual-run (stop-old → seed → verify-new); downtime accepted anytime (approved 2026-11-14).
- `DB_PASSWORD`-style secrets: none (API key + LDAP bind ride with the state).
- `nix fmt` before describe; validation is eval + toplevel builds; switches + seeding + in-app checks are manual.
- POOL state dir never deleted in this plan. Commits via `jj describe` (repo uses jj, not git branches).

## Review Focus

- Root on NFS reads (root_squash → nobody, media ACLs know 359) — expect `runAsUser: 359`; test in Task 1 pins it.
- DRI absent (silent CPU fallback mistaken for HW) — expect `/dev/dri` hostPath + supplementalGroups in the pod spec; test in Task 3 pins HW on the dashboard.
- Wrong image (version drift migrates the old DB) — expect hub-verified `12.4`; test in Task 1 pins it.
- Stale seed (onboarding wizard, empty libraries) — expect library/user counts to match live; test in Task 3 pins it.
- LDAP broken post-move (hostname vs direct IP) — expect seeded config points at `10.200.0.16:6636` and an LDAP login succeeds; test in Task 3 pins it.
